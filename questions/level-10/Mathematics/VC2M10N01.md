# VC2M10N01 — Mathematics

## Snapshot
- **Descriptor:** VC2M10N01. Recognise the effect of using approximations of real numbers in repeated calculations and compare the results when using exact representations.
- **Year level / Learning area:** Years 9–10, Mathematics (Number).
- **Big ideas:**
  - Real numbers include rationals and irrationals — irrational numbers have infinite non-repeating decimals.
  - Using rounded approximations in repeated calculations introduces cumulative error (rounding error compounds).
  - Exact representations (surds, fractions, π) preserve accuracy throughout multi-step calculations.
- **Curriculum hooks:** Numeracy; Critical and Creative Thinking.

## What you are learning
- You are learning to **recognise how rounding errors accumulate** in repeated calculations and to compare approximate and exact approaches.
- You are learning when to use exact forms and when approximations are acceptable.

By the end of this you should be able to:
- Identify when a number is being approximated (rounded) versus represented exactly.
- Demonstrate how rounding errors compound across multiple calculation steps.
- Use exact representations (surds, fractions, π) to avoid cumulative error.
- Make informed decisions about when approximation is acceptable and when exact values are needed.

## Core content

**1. Exact vs approximate representations.** √2 is exact; 1.414 is an approximation. π is exact; 3.14159 is an approximation. 1/3 is exact; 0.333 is an approximation. When you use the exact form in calculations, no error is introduced. When you use an approximation, a small error enters — and can grow. *Quick check:* Which is exact: 22/7 or π? Is 0.667 an exact representation of 2/3?

**2. How rounding errors accumulate.** Calculate √2 × √2. Exactly: √2 × √2 = 2. Using 1.414: 1.414 × 1.414 = 1.999396 (error = 0.000604). Now calculate (√2)¹⁰. Exactly: (√2)¹⁰ = 2⁵ = 32. Using 1.414: 1.414¹⁰ = 28.93... (error ≈ 3.07). The error grew from 0.0006 to over 3 — that's rounding error compounding with repeated operations. *Quick check:* Calculate (1/3) × 3 exactly and using 0.333. What is the error?

**3. Repeated multiplication amplifies error.** Each time you multiply an approximation, the relative error can grow. If you round to 3 decimal places and multiply 20 times, the final error can be significant. This is why engineers and scientists keep exact forms (or many decimal places) during intermediate steps and only round the final answer. *Quick check:* Why might a GPS system use 15 decimal places for π rather than 3.14?

**4. Examples where it matters.** Area of a circle: A = πr². If r = 10 and you use π = 3.14: A = 314. Using π = 3.14159: A = 314.159. Exact: A = 100π ≈ 314.159265... For a single calculation the difference is small. But for a spiral staircase with 50 steps, each involving π, cumulative error becomes noticeable. *Quick check:* A calculation uses π five times in succession. If you use 3.14 each time, how does the error compare to using exact π throughout?

**5. When approximation is acceptable.** For single-step calculations or final answers where precision beyond a certain level doesn't matter (e.g. "about 3 metres"), approximations are fine. For intermediate steps in multi-step calculations, exact forms are preferred. Context determines acceptable precision — building a house needs millimetre accuracy; estimating a crowd size does not. *Quick check:* A recipe calls for 1/3 cup of flour. Does it matter if you use 0.33 cups?

**6. Worked example — the accumulation of rounding error.**
A bank calculates daily interest. The daily rate is 5%/365 = 0.0136986...% per day.

*Follow the thinking:*
- Exact daily factor: 1 + 5/(365 × 100) = 1 + 1/7300 (exact fraction).
- Rounded daily factor: 1.000137 (rounded to 6 d.p.).
- After 1 day on $10,000: exact = $10,001.3699...; rounded = $10,001.37. Difference: $0.0001.
- After 365 days: exact = 10000 × (1 + 1/7300)³⁶⁵ = $10,512.67. Rounded = 10000 × 1.000137³⁶⁵ = $10,512.47. Difference: $0.20.
- After 10 years (3650 days): difference grows to approximately $2.00.
- For a $1 million account, these differences scale proportionally.
- Banking systems use exact fractions or very high precision to avoid this.

**7. Strategies for maintaining accuracy.** (1) Keep exact forms (surds, fractions, π) through all intermediate steps. (2) Only round the final answer. (3) If you must use decimals, use more decimal places than your final answer requires. (4) Be aware that subtraction of nearly-equal numbers magnifies relative error (catastrophic cancellation). *Quick check:* Calculate 1000001 − 1000000.1 exactly versus after rounding each to 5 significant figures.

## Victorian and cultural context

- **Victorian anchor.** Melbourne's Skyrail elevated rail project required calculations with sub-millimetre precision over kilometres — accumulated rounding errors could have misaligned track sections. The Australian Synchrotron operates at precisions where rounding errors in beam calculations would render experiments useless. Surveyors General Victoria maintains cadastral data using exact coordinates. Financial institutions regulated by APRA must use specified precision in interest calculations.
- **Aboriginal and Torres Strait Islander perspective.** Precision in land knowledge — knowing exactly where boundaries, water sources and sacred sites are located — has been maintained over tens of thousands of years through oral traditions and physical markers. The importance of exact knowledge (not "approximately here") in navigation across vast distances parallels the mathematical need for exact representations. Specific cultural knowledge should only be read through published, community-approved material.
- **Multicultural Australian perspective.** Different fields and cultures have different precision norms — medical dosages require high precision; market estimates tolerate approximation. Understanding when precision matters and when it doesn't is a practical skill used in every profession and household.

## Try these scenarios

1. **Everyday.** Calculate the cost of 7 items at $3.33 each (a "third of $10" approximation). Compare with 7 × 10/3 exactly. What is the discrepancy? Would this matter at a checkout?
2. **Civic.** A council measures a circular park's radius as 50 m and uses π = 3.14 to calculate fencing for the circumference. How much fencing do they actually need (using exact π)? What's the shortfall?
3. **Vocational.** A machinist cuts 200 metal pieces, each meant to be √2 cm wide. Using 1.41 cm for each cut, what is the total error after 200 pieces compared with using exact √2 × 200?
4. **Ethical.** A bank uses π = 3.14 in a formula calculating thousands of mortgage repayments. If the error per calculation is tiny, does it matter? Who benefits from the error — the bank or the customer? Discuss.
5. **Cross-cultural.** Zu Chongzhi (5th century China) calculated π ≈ 355/113, accurate to 7 decimal places. Compare the error of 355/113 with 22/7 when calculating the circumference of a circle with diameter 1 km.

## Memorable takeaways
- Exact forms (√2, π, 1/3) carry no rounding error.
- Rounding errors compound with repeated calculations — small errors grow large.
- Keep exact forms through intermediate steps; only round the final answer.
- Context determines acceptable precision.
- Banking, engineering and science demand high precision to avoid accumulated error.

## Watch out for these traps
- **Thinking small errors don't matter.** A 0.001 error multiplied 1000 times can become a 1.0 error — or worse with compounding.
- **Rounding intermediate steps.** Keep exact forms until the final step.
- **Confusing precision with accuracy.** Writing 3.14159265 doesn't help if your measurement was only accurate to 2 decimal places.
- **Assuming calculators are exact.** Calculators round internally — they store a finite number of digits. Very long calculations on a calculator can accumulate error.

**Quick checks (Core content)**
1. *Exact representations.* π is exact; 22/7 is an approximation of π (22/7 = 3.142857..., while π = 3.14159...). 0.667 is not exact for 2/3 (which is 0.6666... repeating).
2. *(1/3) × 3.* Exact: 1. Using 0.333: 0.999. Error = 0.001.
3. *GPS precision.* GPS calculates distances over thousands of kilometres. Even tiny errors in π would accumulate over repeated calculations in positioning algorithms, causing location errors of metres.
4. *Repeated π use.* Each use of 3.14 introduces an error of about 0.00159. Over 5 uses (if multiplied), the error compounds — roughly 0.008 in additive cases but potentially much more in multiplicative chains.
5. *Recipe.* For cooking, 0.33 cups vs 1/3 cup differs by about 1 mL — negligible for a recipe. Approximation is acceptable here.
6. *Banking.* Worked through in example — $0.20 difference after one year on $10,000.
7. *Catastrophic cancellation.* 1000001 rounds to 1000000 (5 sig fig); 1000000.1 rounds to 1000000. Subtraction: 0. Exact answer: 0.9. Relative error: 100%. Subtracting nearly-equal numbers magnifies relative error dramatically.

**Try these scenarios**
1. *Checkout.* 7 × $3.33 = $23.31. Exact: 7 × 10/3 = 70/3 = $23.33̄. Discrepancy: about $0.003. At a checkout, prices are rounded to cents anyway — acceptable.
2. *Park fencing.* C = 2π × 50 = 100π = 314.159... m. Using 3.14: 314 m. Shortfall: 0.159 m ≈ 16 cm. One fence panel might not fit.
3. *Machinist.* Exact total: 200√2 = 282.842... cm. Using 1.41: 200 × 1.41 = 282 cm. Error: 0.842 cm. After 200 cuts, the accumulated piece is almost 1 cm too short.
4. *Bank error.* Even tiny errors matter when multiplied by millions of customers and thousands of calculation steps. Systematically rounding down benefits the bank; rounding up benefits customers. Ethical banking requires specified rounding rules (e.g. "round half even" or banker's rounding).
5. *Zu Chongzhi.* π − 22/7 ≈ −0.00126. π − 355/113 ≈ −0.0000003. For a 1 km circle: C = πd. Error with 22/7: 1.26 m short. Error with 355/113: 0.0003 m = 0.3 mm. Zu Chongzhi's approximation is thousands of times better.

**Stretch task — example shape of a strong answer.** √(10000001) ≈ 3162.27766... and √(10000000) ≈ 3162.27766... On an 8-figure calculator, both display as 3162.2777, giving a difference of 0. The rationalised form: 1/(√10000001 + √10000000) = 1/6324.5553... = 0.00015812... This is accurate because no subtraction of nearly-equal numbers occurs. In programming, 0.1 + 0.2 = 0.30000000000000004 because 0.1 cannot be represented exactly in binary floating point (it becomes a repeating binary fraction). Real-world failures: the 1991 Patriot missile missed a Scud due to accumulated 0.000000095s timing error over 100 hours; the Vancouver Stock Exchange lost value due to truncation errors in index calculations. Strategies: use integer arithmetic for money (count cents), use higher-precision libraries, avoid subtracting nearly-equal numbers, and use compensated summation algorithms (Kahan summation).

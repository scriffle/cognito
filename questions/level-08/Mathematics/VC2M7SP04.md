# VC2M7SP04 — Mathematics

## Snapshot
- **Descriptor:** VC2M7SP04. Design algorithms involving a sequence of steps and decisions that will sort and classify sets of shapes according to their attributes, and describe how the algorithms work.
- **Year level / Learning area:** Years 7–8, Mathematics (Space).
- **Big ideas:**
  - An algorithm is a step-by-step procedure that always produces a correct result.
  - Decision points (yes/no questions about attributes) sort shapes into categories.
  - A well-designed algorithm is clear enough for anyone to follow without guessing.
- **Curriculum hooks:** Numeracy; Critical and Creative Thinking; Technologies (Digital).

## What you are learning
- You are learning to **design algorithms** that sort and classify shapes by their **attributes**.
- You are learning to **describe how an algorithm works** using sequences, decisions and clear language.

By the end of this you should be able to:
- Write a step-by-step algorithm that classifies a shape into the correct category.
- Use decision points (if–then questions) based on measurable attributes.
- Represent your algorithm as a flowchart or structured text.
- Test your algorithm on a range of shapes to check it works.

## Core content

**1. What is an algorithm?** An **algorithm** is a finite sequence of clear steps that solves a problem. In mathematics, it must work every time for every valid input. A recipe is an everyday algorithm; a classification flowchart is a mathematical one. *Quick check:* What makes an algorithm different from a guess?

**2. Attributes for classification.** Shapes have measurable **attributes**: number of sides, side lengths (equal or unequal), angle sizes (right, acute, obtuse), parallel sides, lines of symmetry. Your algorithm uses these as decision criteria. *Quick check:* Name three attributes you could measure on a quadrilateral.

**3. Decision points.** A **decision** asks a yes/no question about an attribute: "Does it have exactly 3 sides?" If yes, go one way; if no, go another. Each decision narrows the possibilities. *Quick check:* What yes/no question would separate triangles from all other polygons?

**4. Sequencing decisions.** The order of questions matters. A good algorithm asks the most discriminating question first. To classify quadrilaterals: start with "Are all four angles 90°?" (separates rectangles and squares from the rest) before asking "Are all sides equal?" (separates squares from rectangles). *Quick check:* Why does asking about angles before sides help efficiency?

**5. Flowchart representation.** A **flowchart** uses ovals (start/end), rectangles (actions) and diamonds (decisions with yes/no branches). Drawing a flowchart makes the logic visible and testable. *Quick check:* What shape represents a decision in a flowchart?

**6. Worked example — classifying triangles at the Melbourne Museum.** A museum education officer designs a sorting activity for visitors. The algorithm:
Step 1: Count the sides. If not 3, output "Not a triangle" and stop.
Step 2: Are all three sides equal? If yes → "Equilateral." Stop.
Step 3: Are exactly two sides equal? If yes → "Isosceles." Stop.
Step 4: Output "Scalene." Stop.
Test: a shape with sides 5, 5, 5 → Step 2 says yes → Equilateral. A shape with sides 3, 4, 5 → Step 2 no, Step 3 no → Scalene. *Follow the thinking:* define the input → order the questions from most to least restrictive → test with examples → confirm every path produces a correct output.

**7. Testing and debugging.** Run your algorithm on several shapes, including edge cases. Does a square get classified correctly by a quadrilateral algorithm? Does a regular hexagon pass through a polygon sorter without error? If a shape lands in the wrong category, adjust the order or wording of your decision points. *Quick check:* Why is testing with edge cases important?

## Try these scenarios

1. **Everyday.** You have a bag of mixed polygon tiles. Design a three-question algorithm that sorts them into triangles, quadrilaterals and "other polygons."
2. **Civic.** Yarra City Council needs to classify road signs by shape for a database. Design an algorithm that identifies circular, triangular, rectangular and octagonal signs.
3. **Vocational.** A quality-control officer at a tile factory must sort tiles as "pass" or "fail" based on whether they are the correct shape (square) with sides within 1 mm of 200 mm and angles within 1° of 90°. Write the algorithm.
4. **Ethical.** A classmate's algorithm classifies a square as "not a rectangle." Identify the error and explain how to fix it.
5. **Cross-cultural.** Design a flowchart that classifies Australian coins by shape (some are circular, the 50-cent coin is a dodecagon). Include at least three decision points.

## Memorable takeaways
- An algorithm is a step-by-step procedure that always produces a correct result.
- Decision points ask yes/no questions about measurable attributes.
- Order your questions from most to least discriminating.
- Represent the algorithm as a flowchart to make the logic visible.
- Always test with a range of shapes, including edge cases.

## If you need more support
- **Sentence stems to start your writing.** "Step 1: Check ___. If yes, then ___. If no, go to step ___. The shape is classified as ___."
- **Words to keep close.** algorithm, decision, attribute, flowchart, classify, sort, input, output, edge case, test.
- **Try this picture.** Draw a flowchart with three diamond-shaped decision boxes and four rectangular output boxes. Connect them with arrows labelled "Yes" and "No."
- **A different way to show what you know.** Cut out ten different polygon shapes. Hand them and your written algorithm to a classmate. Can they sort every shape correctly without asking you questions?

## Stretch yourself
Design a complete classification algorithm for quadrilaterals that correctly identifies squares, rectangles, rhombuses, parallelograms, trapeziums and kites. Present it as both a flowchart and a set of numbered steps. The algorithm must handle the hierarchy correctly — a square must be identified as a square (not just as a rectangle or rhombus). Test your algorithm on at least five different quadrilaterals, including a square, a non-square rectangle, a non-square rhombus, a trapezium and a kite. Show the path each test shape takes through your algorithm and confirm the output is correct. 250–300 words.

## Watch out for these traps
- "Any order of questions works." Order matters — a poorly ordered algorithm can misclassify shapes or be inefficient.
- "A square fails the rectangle test." A square meets all rectangle requirements. Your algorithm must check for the most specific category first (square before rectangle).
- "Testing one shape is enough." You need to test shapes from every category, including edge cases, to confirm your algorithm is correct.
- "An algorithm is just a list." It is a structured sequence with decisions — not a flat list of facts.

## Model responses

Use these to check your own thinking after you have had a go.

**Quick checks (Core content)**

1. *Algorithm vs guess.* An algorithm follows defined steps and always works; a guess is unreliable and may produce wrong answers.
2. *Three quadrilateral attributes.* Number of parallel side pairs, side lengths (equal or not), angle sizes (right angles or not).
3. *Question to separate triangles.* "Does the shape have exactly 3 sides?"
4. *Angles before sides.* Asking about right angles first eliminates many categories quickly (only rectangles and squares have four right angles), making the remaining decisions simpler.
5. *Flowchart decision shape.* A diamond.
6. *Why test edge cases.* Edge cases (e.g., a square tested by a rectangle algorithm) reveal where decision order or wording causes misclassification.

**Try these scenarios**

1. *Polygon sorter.* Q1: "Exactly 3 sides?" → Triangle. Q2: "Exactly 4 sides?" → Quadrilateral. Q3: → Other polygon.
2. *Road signs.* Q1: "Is it circular?" → Circle. Q2: "Is it triangular?" → Triangle. Q3: "Is it octagonal?" → Octagon. Q4: → Rectangle.
3. *Tile quality control.* Step 1: "Is it a quadrilateral with 4 equal sides?" If no → Fail. Step 2: "Are all angles within 1° of 90°?" If no → Fail. Step 3: "Are all sides within 1 mm of 200 mm?" If no → Fail. Step 4: → Pass.
4. *Square misclassified.* The algorithm checked "Are all sides equal?" before checking for right angles. Fix: check for four right angles first (→ rectangle family), then check for equal sides (→ square).
5. *Coin classifier.* Q1: "Is it circular?" If yes → 5c, 10c, 20c, $1 or $2. Q2: "Is it a dodecagon (12 sides)?" If yes → 50c. Q3: Further size-based decisions to identify denomination.

If no → Q7: "Two pairs of adjacent equal sides?" If yes → Kite. If no → Irregular quadrilateral. Tested on five shapes with correct paths traced.

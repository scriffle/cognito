# VC2M8A04 — Mathematics (Short)

## Snapshot
- **Descriptor:** Use algorithms and related testing procedures to identify and correct errors.
- **Year / Area:** Years 7–8, Mathematics.
- **Big ideas:** Algorithms must be tested systematically. Errors can be logic, computation or sequencing. Testing with known answers and edge cases reveals hidden errors.

## What you are learning
- You are learning to **test algorithms** systematically and to **identify and correct errors**.
- You should be able to trace through an algorithm, locate the faulty step and classify the error type.

## Core content

An **error** is any point where an algorithm produces an incorrect output. Types: **logic errors** (wrong rule), **computation errors** (wrong arithmetic within a correct rule), **sequencing errors** (right steps, wrong order).

**Tracing** (dry run) means following each step with a specific input, recording variable values in a trace table. This reveals exactly where the output goes wrong.

**Testing with known answers.** Choose inputs where you know the correct output. If actual ≠ expected, the trace shows which step failed. Always test with **multiple inputs** — one passing test proves nothing.

**Edge cases** are extreme or unusual inputs (zero, one, maximum, empty). Algorithms most often fail at boundaries.

**Worked example — perimeter algorithm.** Student writes: Step 1: Read *l*, *w*. Step 2: *P = l + w*. Step 3: Output *P*. Test: *l = 5*, *w = 3* → output 8. Expected: 16. Trace: Step 2 is wrong — should be *P = 2(l + w)*. Logic error. Fix and re-test: *2(5 + 3) = 16*. Correct. *Follow the thinking:* test → compare → trace → classify → fix → re-test.

**Iterative correction.** Fixing one error may reveal another. After each fix, re-run all test cases — a fix can break something that previously worked.

**Cultural context.** Aboriginal seasonal calendars self-correct against ecological indicators (bird arrivals, plant flowering) — algorithmic thinking with built-in testing. Melbourne's myki system, VicRoads traffic signals and Melbourne Water flood-prediction algorithms all depend on rigorous testing procedures.

## Memorable takeaways
- Trace step by step — compare actual with expected at each step.
- Classify errors: logic, computation or sequencing.
- Test with normal inputs, known answers and edge cases.
- Fix, then re-test everything.

## Watch out for these traps
- "Works for one input, works for all." Multiple tests are essential.
- "The error is always in the last step." It may originate earlier and only become visible at the end.
- "Edge cases don't matter." Most real-world errors occur at boundaries.
